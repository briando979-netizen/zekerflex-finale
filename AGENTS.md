# AGENTS.md — ZekerFlex (instructies voor coding-agents: Codex, Claude, de ZekerFlex Bouwer)

ZekerFlex is een Nederlands flexwerk-/uitzend-/zzp-marktplaatsplatform.
**Stack:** Next.js (App Router) · TypeScript (strict) · Prisma · Tailwind · draait op de **eigen TransIP-VPS** (Docker Compose + Caddy, `docker-compose.vps.yml`).

## Gouden regels (ALTIJD volgen)

1. **Verifieer vóór elke commit** en lees de output:
   - `npx tsc --noEmit -p .`  (moet 0 fouten geven)
   - `npx eslint <gewijzigde bestanden>`  (moet schoon zijn)
   - `npx vitest related --run <gewijzigde bestanden>` — dit is wat de live-zetter doet; draai het zelf, niet `vitest run` (alles)
   - Raak je `prisma/schema.prisma` aan: `npx prisma validate` (met `DATABASE_URL` en `DATABASE_URL_UNPOOLED` gezet, anders keurt hij elk schema af). 8 nov werd het schema bij één commit ongeldig en bouwden 147 commits erop door voordat iemand het zag; main is toen teruggezet (tak `bewaard-2026-11-08`).
   Commit/push **alleen** als alles schoon is.
2. **Pushen naar `main` is nog niet live, maar wel de volgende uitrol.** Live zetten gaat via Admin → ZekerFlex AI → Live zetten (de live-zetter op de VPS) of `deploy/scripts/vps-update.sh`; die zetten GitHub `main` live. Migraties draaien **niet** vanzelf: alleen met `ZF_MIGREER=1`, na een droge proef (`BEGIN … ROLLBACK`). Push dus alleen gecontroleerde wijzigingen.
3. **Strikte TypeScript:** `noUncheckedIndexedAccess` (guard `arr[i]` met `?? …`) en `exactOptionalPropertyTypes` (nooit `prop: undefined` toekennen; laat de key weg of type `| undefined`).
4. **Volg de bestaande stijl** (naamgeving, comment-dichtheid, patronen van omringende code). Kijk eerst hoe iets elders is gedaan.
5. **Kleine, omkeerbare diffs.** Geen destructieve/riskante commando's. Bouw niet opnieuw wat al bestaat — het platform is zeer compleet; zoek echte gaten.
6. **Alle zichtbare tekst is gewoon Nederlands** (de eigenaar leest geen Engels).

## Valkuilen (lessen uit eerdere fouten)

### Tijd en gegevens

- **Tijd:** de server draait in UTC. Gebruik `lib/time/amsterdam.ts` (`amsterdamDayKey`, `amsterdamClock`, `amsterdamStartOfDay`, …); nooit `getHours()`/`toLocale*` zonder `timeZone: "Europe/Amsterdam"`. Ook in client-componenten die op de server renderen (anders hydratiefout #418). Tijden in `.ics` altijd UTC met `Z` (`toISOString`). Een `datetime-local`-waarde ("2026-11-05T09:00", zonder zone) op de server nooit met `new Date()` inlezen, maar met `parseAmsterdamLocal()`. Dagen optellen met `Date.UTC(y, m - 1, d + n)` + `amsterdamToUtc()`, niet met `setDate` op een tijdstip.
- **Annuleringen** tellen alleen tegen een werker via het begin van `cancelReason` ("Afgezegd door flexwerker…", "Niet opgekomen…"; `lib/profile/card.ts`). Een nieuw annuleringspad krijgt dus een herkenbaar begin.
- **Promise.all uitbreiden:** controleer de volgorde van de destructuring.
- **Na een PATCH** de teruggegeven serverversie overnemen in de lijst, niet lokaal één veld bijwerken (de server kan bijeffecten hebben).
- **PUT /api/me/fiscal voegt alleen meegestuurde sleutels samen** (13 nov): een scherm stuurt alleen wat het verandert, anders zet een oudere stand in de browser een nieuwere keuze stil terug (de loonheffingskorting).
- **Gedeelde staat in het geheugen** (wachtrijen, caches) via `globalThis`: Next bundelt routes apart, dus een gewone module-variabele bestaat per bundel.
- **Bestanden die de app zelf schrijft** (uploads, Studio-foto's) horen op het opslagvolume (`storage/`, volume app-storage), nooit in `public/`: de container wordt bij elke uitrol vervangen en alles daarin is dan weg (`lib/ontwerp/fotos-store.ts`, `lib/ontwerp/media.ts`).
- **Grote uploads:** met middleware kapt Next elke request-body stil af op `middlewareClientMaxBodySize` (in `next.config.mjs`, nu 210mb; standaard 10 MB, alleen een waarschuwing in het log). Staat een route grotere bestanden toe, verhoog dan die grens mee.
- **AuditLog** heeft bewust geen relatie met User (de hashketen); voeg die niet toe.

### Veiligheid en privacy

- **JSON-LD:** altijd via `ldJson()` uit `lib/seo/json-ld.ts`, nooit `JSON.stringify` in een `<script>`-tag (XSS).
- **AVG:** een nieuwe KV-sleutel per gebruiker → het voorvoegsel in `ERASABLE_KV_PREFIXES` (`lib/privacy/user-kv.ts`), anders ontbreekt hij bij export/wissen. Uitvoer naar gasten/klanten (account-API, export) bevat geen interne teamvelden: filter op één plek.
- **ID-documenten (MRZ en chip) bevatten het BSN** in het vrije veld: BSN uit MRZ of chip alleen via hashBsn + laatste 4, na bevestiging door de werker (`lib/kyc/bsn-uit-document.ts`, alleen uitzendkracht en NL-document); nooit ruw teruggeven, bewaren of loggen (`lib/kyc/mrz.ts`, `lib/kyc/chip/`). Sinds aug 2021 staat het BSN niet meer in MRZ of chip, maar alleen in een QR-code op de achterkant (ID-kaart) of achter de datapagina (paspoort): `lib/kyc/bsn-qr.ts` (server, sharp + jsQR, verkleinen tot ±1080/1600 breed: op volle grootte vindt jsQR niets), zelfde regels. Een documentnummer dat de OCR verkeerd las alleen herstellen als precies één variant klopt: posities met hetzelfde gewicht (0 en 3, 1 en 4, …) zijn met geen enkel controlecijfer uit elkaar te houden, ook niet met het samengestelde.
- **Een chip lezen kan niet in een browser** (Web NFC leest alleen NDEF-stickers): alleen in de Android-app (`android-twa/app/src/main/java/com/zekerflex/ChipActivity.java`, JMRTD). `android-twa/` staat bewust buiten git, met de release-sleutel: maak een reservekopie vóór elke wijziging, en zet een nieuwe versie in `app/build.gradle` én `twa-manifest.json`. Een chip is pas "echt" met een CSCA van dat land in `storage/csca` (owner-todo `chip-csca`); controleer hashes, handtekening, keten én de geldigheid van DS en CSCA (`lib/kyc/chip/sod.ts`).
- **Nooit capability-URL's in een log** (push-endpoints, getekende links, tokens in een querystring); log alleen de host.
- **Herkomstcontrole achter Caddy:** `request.url` is `app:3000`; vergelijk `Origin` met `Host`/`X-Forwarded-Host` (`lib/rijschool/herkomst.ts`), anders krijgt elke echte POST een 403.
- **Een CSP hoort bij het document:** wie via een `<Link>` navigeert, houdt de CSP van de eerste pagina. Een versoepeling (bijv. `frame-src 'self'`) dus per hele omgeving zetten (alle `/admin`), niet per losse route (`lib/security/csp.ts`). Een pagina die zelf frames nodig heeft (ZekerFlex OS, `/os`) bereik je vanuit de andere schermen met een gewone `<a>` (volledige paginalading), anders blijven de vensters leeg (`tests/os-ingang.test.ts`).
- **Namen vergelijken** (ID-document, bank-inlog, profiel) alleen met `naamGelijk`/`banknaamPast` uit `lib/kyc/naam-match.ts`, nooit met gesorteerde letters: dan zijn "Jan Smit" en "Tim Jans" dezelfde naam en keurt de controle het document van een ander goed (9 nov). Een andere achternaam blijft altijd handmatig.
- **Gegevens van het hele platform filteren:** `listCounterOffers()` (`lib/offers/store.ts`) en vergelijkbare KV-lijsten geven álle bedrijven terug. Tel of toon alleen wat bij de eigen klussen/vestigingen hoort (9 nov: "Reacties (N)" telde andere bedrijven mee).
- **Nieuwe openbare API-route** → `lib/auth/public-routes.ts` + `tests/public-routes.test.ts`.
- **Nieuwe openbare uploadroute** (formData met een bestand, of request.arrayBuffer()) → in `UITZONDERINGEN` in `lib/http/openbare-grens.ts`: de middleware weigert anders alles boven 1 MB met 413 (bewaker `tests/openbare-grens-middleware.test.ts`).
- **Openbare route die een body leest:** begrens eerst `Content-Length` (422, nooit 403) vóór `formData()`/`json()`/`arrayBuffer()` en vóór een tokencontrole; de server laat tot 210 MB door. Codes en tokens in de body, nooit in het adres (dan staan ze in geen log). Voorbeeld: `/api/id-overdracht/document-live`.
- **Storingen in Redis/KV mogen inloggen niet blokkeren** (fail-open voor slot/limiet).
- **Geen 403 voor iets wat een gewone sessie vaak raakt** (alleen-lezen, inspectie): CrowdSec telt een reeks 403's als inbraakpoging en blokkeert het hele IP (ook ssh). Gebruik 423 met een eigen `code`. Testen vanaf een nieuw IP: eerst `cscli allowlists add zekerflex-eigen <ip>`; het IP van de pc van de eigenaar wisselt (mobiel).
- **Testen met mail of bedrijven:** alleen testadressen; nooit een echte lead. Let op: sendMail houdt alleen `.test`/`.example`/`.invalid`/localhost in de eigen postbus (`isReservedTestAddress`); `@example.com` gaat wél via SMTP (en kaatst terug). En een melding die je code naar een intern adres stuurt (sales@, info@) gaat altijd echt, ook bij een testklant: sla die over voor testadressen (zie `lib/domeinen/bestelling.ts`).

### Geld

- **Stripe-webhook:** elke functie een eigen tak op een metadata-sleutel, idempotent via unieke kolommen (Stripe stuurt soms dubbel). Een eigenaar-todo `stripe-webhook-handtekening` staat klaar als het webhook-secret niet bij het endpoint hoort (de fouten zeggen "No signatures found").

Een nieuwe koopknop voor iets digitaals (abonnement, module, domein, pakket) dus in `<NietInIphone>` (`components/app/NietInIphone.tsx`); server: `inIosApp()`. Betalen voor werk, de shop en fysieke dingen mag wel. Pushes gaan via `sendUserPush` vanzelf ook naar de iPhone (APNs, `lib/notifications/push/apns.ts`).

Verdiensten gaan altijd naar de eigen IBAN; voorschot voor zzp'ers en de doorverwijsbonus liepen via de bank en staan dus ook uit. Bouw niets nieuws op de bank en beloof het nergens (site, chat, advertenties). Alleen wat nu echt kan, staat op de site.

### Schermen

- **Werker-app (`/dashboard`) is vijftalig** (NL/EN/PL/RO/UK): nieuwe tekst in `lib/i18n/freelancer.ts`, client via `useFT()`. Importeer nooit `dictionary-en`, `lib/i18n/server` of `FREELANCER_DICTS` in een client-bestand dat de shop laadt (`tests/i18n-bundle.test.ts`). Een onderdeel dat werker én werkgever delen krijgt een `texts`-prop met NL-standaard (zoals `components/auth/two-factor-texts.ts`).
- **De werkgeversapp (`/werkgever`) is Nederlands en Engels:** nieuwe tekst in `lib/i18n/dictionaries.ts` en `dictionary-en.ts` (server `getDict()`, client `useT()`). `tests/werker-taal-bewaker.test.ts` en `tests/werkgever-taal-bewaker.test.ts` laten een nieuwe vaste Nederlandse zin falen in wat `/dashboard` of `/werkgever` laadt; de basislijn (`tests/werkgever-taal-basislijn.json`, en de lijst bovenin de werker-test) mag alleen kleiner worden.
- **De werker-app is open (12 nov, eigenaar):** iedereen ziet alles; alleen reageren wacht op de onboarding. Een nieuw reageerpad (aanmelden, aanbod aannemen, overnemen) roept `eisOnboardingVoorReageren` aan (412, geen 403); de stappen staan bovenaan Klussen. Tweestapsverificatie is optioneel (aanbeveling, geen stap). Testaccounts (.test) vallen buiten die regel: test hem live met een vlag of een eigen proefaccount, niet met .test.
- **Push aan een werker** gaat in zijn app-taal: `sendLocalizedPush()` (`lib/notifications/localized-push.ts`) met de tekst in `WORKER_PUSH` (`lib/i18n/worker-push.ts`, vijf talen), nooit een losse `sendUserPush` met Nederlandse tekst. Pushes aan opdrachtgevers blijven Nederlands.
- **Een systeembericht in de chat** (`postMessage(…, "system")`) stuurt géén push. Moet iemand het echt weten (tijd verzet, geannuleerd, claim), stuur dan zelf een push mee.
- **Client-componenten** importeren nooit iets dat prisma, kv, mail of zod meeneemt; zet gedeelde lijsten/hulpjes in een los, puur bestand.
- **`sr-only` in een vegende rij** (`overflow-x-auto`): die tekst is `position: absolute`; zonder gepositioneerde ouder (`relative`) binnen de rij ontsnapt hij aan het afknippen en maakt hij de hele pagina breder dan het scherm (5 nov: /shop scrollWidth 841 op 390). Geef de kaart of het element eromheen `relative`.
- **useEffect geeft nooit een waarde terug** behalve een opruimfunctie: schrijf `useEffect(() => { void load(); }, …)`, nooit `useEffect(() => load(), …)` of `useEffect(() => ref.current?.scrollIntoView(…), …)`. Nieuwe Chromium geeft bij `scrollIntoView` een object terug en `load()` een Promise; React roept dat als cleanup aan en de pagina valt om ("u is not a function", 6 nov: de assistent-pagina).
- **Een vaste tabel bevragen met `Object.hasOwn(tabel, v)`**, niet `v in tabel`: anders telt `constructor` uit de URL als geldige sleutel (`/p/<slug>/constructor` gaf een 500).
- **Geen component binnen een component** definiëren (velden verliezen hun focus) en **geen `<form>` binnen een `<form>`**.
- **Een bevestiging vóór iets onomkeerbaars (indienen) is een eigen stap**, geen paneel dat je per ongeluk wegtikt: daarna stond de werker bij de camera zonder knop "Indienen" (13 nov, `IdScan` stap `controle`).
- **ID-scan zonder bestandskeuze** (13 nov, eigenaar): automatisch (geen knop) óf zelf (alleen de knop), met een wissel na 20 s; geen camera = verder op de telefoon (QR). Geen mengvorm en geen `type="file"` terugzetten (`tests/id-auto-of-zelf.test.ts`).
- **Een servercomponent geeft nooit een functie door aan een clientcomponent** ("Functions cannot be passed directly to Client Components" → de hele pagina valt om). Een tekst met een invulling wordt dus gewone tekst met een plaatshouder (`"{naam} praat"`, `{ een, meer }` voor enkel-/meervoud) die de client invult (`vulIn`/`vulAantal` in `lib/locatie/teksten.ts`). 6 nov sloopte dit `/dashboard/voertuig` en `/dashboard/portofoon`.
- **Een hulpje dat zowel de pagina (server) als het scherm (client) nodig heeft, staat in een puur bestand**, niet geëxporteerd uit een `"use client"`-bestand: dat geeft "Attempted to call isTab() from the server but isTab is on the client" (6 nov: `/werkgever/op-locatie`, opgelost met `lib/locatie/tabs.ts`).
- **Chat (`components/chat/`):** de chat is `InboxPage`; het berichtpaneel van `ChatDock` staat uit (`hideDock`), die doet alleen bellen. Elke poll maakt een nieuwe berichtenlijst: scroll dus nooit op `messages` als dependency, maar via `useStickyScroll` (op het laatste bericht-id; anders springt het gesprek elke 3 s naar beneden). Een optimistisch bericht dat de server weigert krijgt `failed` + "Opnieuw", nooit een klokje dat blijft staan. Meldingen via de eigen balk (`say`), geen `window.alert`.
- **Portals en events:** React stuurt touch-/klik-events uit een `<Portal>` (paneel, viewer) langs de voorouders in de React-boom. Een rij met eigen touch-handlers (lang drukken, vegen) controleert daarom `rowRef.current.contains(e.target)`.
- **Admin:** elke pagina met de kit (`components/admin/kit.tsx` + `kit-client.tsx`: PageHead, KpiStrip, Panel, Chart, DataTable), opgenomen in `ADMIN_HUBS` (`lib/admin/nav.ts`) en strikt `PLATFORM_ADMIN` (`tests/admin-access.test.ts` en `tests/admin-nav.test.ts` bewaken dat).
- **Elk soort bedrijf heeft een eigen dashboard** (10 nov): personeel, rijschool, horeca, website, webshop (`lib/werkgever/werkruimte.ts`). Het dashboard personeel heeft alleen personeel inhuren; rijschool en horeca tonen elk tabblad van hun beheer als eigen menu-item (`lib/rijschool/tabs.ts`, `lib/horeca/tabs.ts`, adres `?tab=<id>`); website en webshop zijn de studio. Een nieuw menu-item = een sleutel in `menuVoor()` plus adres, label en icoon in `app/werkgever/layout.tsx` (`tests/werkgever-werkruimte.test.ts`). Welke dashboards een bedrijf heeft: KV `werkruimte:<tenantId>` plus wat het gebruikt (klussen → altijd personeel); welk open is: cookie `zf_dashboard` per browser, gezet door `POST /api/werkgever/dashboard/wissel` (de wisselaar bovenaan de zijbalk). Een nieuw scherm van één dashboard: zet het pad in `dashboardVanPad()`, dan wisselt het menu mee bij een link uit een mail.
- **Kleuren:** één kleur = één betekenis — groen doen, blauw `plan` gepland, amber `warn` wacht op jou, violet `trust` verificatie, goud `money` geld, rood probleem. Kleuren die een klant kiest: tekst- en knopkleur via `lib/rijschool/kleuren.ts`; oranje op licht haalt geen AA voor kleine tekst (gebruik de donkere variant).
- **Donkere modus (werker- en werkgeversapp)** werkt alleen via de regels `.app-scope[data-theme="dark"] .<klasse>` in `app/globals.css`; Tailwind `dark:` volgt het systeem, niet de themaknop. Een kleurklasse zonder zo'n regel (ook `hover:…`) blijft licht en wordt onleesbaar: voeg hem daar toe, met de lichte tint uit het donkere beheerthema.
- **Toegankelijkheid:** foutmeldingen in formulieren krijgen `role="alert"`; labels aan velden koppelen.
- **Snelheid mag het uiterlijk nooit veranderen:** bewijs het met schermafbeeldingen per scrollpositie, vóór en na.
- **Lettertypes** staan zelf gehost (`public/fonts`, `app/fonts.css`); de build haalt niets bij Google.
- **Eigen `opengraph-image.tsx`** werkt alleen met `canonical(path, { fileImage: true })` (`lib/seo.ts`).
- **`sitemap.ts`/`robots.ts` zonder `revalidate` of dynamische API zijn statisch:** Next maakt ze tijdens de build, zonder database (gegevens ontbreken dan stil). Zet `export const revalidate = …` en controleer live dat `x-nextjs-cache`/`lastmod` niet de buildtijd blijven.
- **sharp** heeft geen lettertypes in de container: geen tekst in een SVG die naar PNG gaat, alleen vormen.

### Klantsites en websitevoorstellen

- Gebouwde sites (`lib/sites/render.ts`) hebben geen scripts en een sandbox-CSP; alles komt van de site zelf (foto's via `media/`, lettertypes via `assets/fonts/`), nooit van een derde partij.
- Bestaande klantsites en verstuurde voorstellen nooit ongevraagd van uiterlijk laten veranderen: een nieuwe stijl of nieuw blok is standaard alleen voor nieuwe sites; de klant kiest zelf.
- Een voorstel mailt nooit vanzelf (een mens verstuurt) en heeft een band "niet de officiële website", noindex, geen LocalBusiness-JSON-LD en een dicht formulier.

### Testen en fouten zoeken

- Pas je een bestaande route of functie aan, draai dan alle tests die dat pad raken (zoek in `tests/`), niet alleen je nieuwe.
- Pure hulpjes in `.ts`, niet `.tsx` (vitest leest geen JSX). Module met prisma testen: `vi.mock("@/lib/prisma", () => ({ prisma: {} }))`. `AppError.validation` geeft 422. Geen `.refine` binnen `z.discriminatedUnion`.
- **Het antwoord van een model lees je soepel, niet streng.** Een model levert soms een object waar tekst hoort; `schema.parse` gooit dan de hele ronde weg ("invalid_type, expected string, received object", 6 nov: de orchestratiecyclus sloeg niets op). Maak er tekst van, sla één onbruikbaar item over en ga door (`lib/orchestration/antwoord.ts`). Dat telt zwaarder zodra "alles gratis" aan staat en ons eigen, kleinere model antwoordt.
- **Tests met datums worden tijdbommen:** de live-controle draait `vitest related` in UTC en houdt dan élke uitrol tegen. Bevries de klok (`vi.useFakeTimers({ toFake: ["Date"] })` + `vi.setSystemTime`), geef een datum altijd een zone (`"2026-09-02T06:30:00+02:00"`, nooit zonder) en geef een `now`-parameter door aan alles wat een tijd vastlegt.
- **Fouten zoeken:** eerst het foutenlogboek (Admin → Systeem → Foutmeldingen, `lib/ops/error-journal.ts`); meet vóór je een oorzaak noemt.
- **Taken voor de eigenaar** (sleutels, accounts, iets in een extern portaal) horen in `lib/admin/owner-todos.ts` (Admin → Te doen); aan/uit zonder uitrol via `lib/flags`.

### Gedeelde werkmap en uitrollen (sessies op de pc; de Bouwer heeft een eigen kopie)

- Meerdere sessies delen één werkmap en `main`. Push op sha (`git push origin <sha>:main`) en rol een vaste hash uit, nooit HEAD. Gewoon pushen alleen als `git merge-base --is-ancestor origin/main main` waar is; anders je eigen commits in een losse worktree op `origin/main` cherry-picken. Nooit `pull --rebase`/`--autostash` in de gedeelde map (dat raakt onaf werk van anderen). Faalt tsc door onaf werk van een ander, controleer dan HEAD + je eigen bestanden in een losse `git worktree`.
- **Auto-uitrol (14 nov, `deploy/bouwer/README.md` punt 3):** staat de vlag `auto-uitrol` aan (standaard uit), dan rolt de server main vanzelf uit na 3 minuten rust en een schone controle (prisma validate, tsc, eslint, tests, bewakers), nooit bij een rode controle of een wachtende migratie (die blijft handwerk). Een push naar `main` kan dus binnen enkele minuten live staan: push alleen wat gecontroleerd is. Noodrem: Beheer → Live zetten. GitHub Actions blijft uit (kosten); `.github/workflows.disabled/` doet niets.
- **Twee takken die dezelfde functie raken:** git kan ze zonder conflict samenvoegen en toch iets dubbel zetten (13 nov: twee keer `const before` in de fiscal-route). Lees het samengevoegde bestand na vóór controle-tak.
- Vóór een uitrol: staat er op `main` een migratie van een ander die nog niet op prod is (`_prisma_migrations`), rol dan niet blind `main` uit. Meld een uitrol vooraf en "klaar" erna; test live nooit tijdens de uitrol van een ander.
- **Controle op de server vóór main:** push je werk naar een eigen tak en draai `controle.mjs` in de Bouwer-container (`docker exec zekerflex-bouwer-1 node /opt/bouwer/controle.mjs --sha <sha> --vanaf <live>`): tsc op het hele project (incrementeel, 10–60 s), eslint en vitest related in UTC. De pc heeft maar 8 GB: geen volledige tsc lokaal als er meer sessies draaien. Tijdens een uitrol herstart die container en breekt de controle af (exit 137): wacht tot de uitrol klaar is. De gedeelde `node_modules` heeft één Prisma-client: draai `prisma generate` alleen vanuit het schema van main.
- **Next zet `127.0.0.1` in een querystring om naar `localhost`** (NextURL): een API die een IP-adres als `?ip=` krijgt, ziet voor het loopback-adres `localhost`. Test zulke routes met een echt adres (bv. het Docker-adres van de container), niet met 127.0.0.1.
- **Geheugen van het eigen AI-model telt mee bij elke uitrol.** De build vraagt ±4 GB, het eigen model (gemma3:4b + granite-embedding) piekt op ±4,9 GiB (gemeten 13 nov; met `mem_limit: 4g` volgde elke ochtend een OOM-kill, nu 5632m). Op 8 GB liep op 7 nov het wisselgeheugen vol: load 138, 20 minuten honderden 502's. Sinds de upgrade naar 16 GB (7 nov) blijft Ollama draaien; `vps-update.sh` stopt hem alleen nog als er vóór het bouwen minder dan 6 GB vrij is (en start hem daarna, trap); de cron `/api/internal/ai/warm` laadt het model weer en meldt een uitrol niet als storing. Kies je een groter model, meet dan eerst `docker stats` tijdens een uitrol. Een model kiezen gebeurt op de server zelf met echte taken (`ai-meting.sh`-aanpak), niet op naam.
- **`docker exec … psql` in de postgres-container:** zonder `init: true` is de postmaster PID 1 en erft hij elk exec'd psql-proces; eindigt dat met exitcode ≥ 2 (SQL-fout met `ON_ERROR_STOP`, kapotte pipe), dan herstart Postgres 17+ álle verbindingen (6 nov: twee keer "terminating any other active server processes", 16× "Server has closed the connection" in de app). Sinds `init: true` in compose is dat weg; houd psql-aanroepen toch netjes (geen `|` die vroeg sluit, fouten afvangen).
- **Nieuwe dienst in `docker-compose.vps.yml`:** zet hem ook in de `up -d`-regel van `deploy/scripts/vps-update.sh`, anders start een uitrol hem niet. Een poort die al bezet is (coturn heeft 3478 én 3479) laat `up -d` de container zonder netwerk achter: de app ziet hem dan niet (EAI_AGAIN). Controleer na de eerste uitrol `docker inspect` op het netwerk.
- **CrowdSec blokkeert ook jou.** Vraag nooit vanaf het eigen adres bekende lekke paden op (/.env, /wp-login.php, /phpmyadmin) en laat een alleen-lezen inspectiesessie geen reeks 403's maken: dat is voor CrowdSec een scanner en het pc-adres gaat 4 uur dicht (ook ssh). Het adres van de pc wisselt (mobiel): controleer vóór zulke tests `cscli allowlists inspect zekerflex-eigen` en voeg het huidige adres toe. Zit je buitengesloten: ander netwerk (hotspot) of de TransIP-console, dan `cscli decisions delete --ip <ip>`. Twilio-webhooks: bij een verkeerd `TWILIO_AUTH_TOKEN` volgen reeksen 403's van Twilio (een foute handtekening is echt geen toegang, dus de 403 blijft); controleer dan eerst het token en daarna `cscli decisions list`.
- **Een standaard in compose (`${WHISPER_ENABLED:-true}`) telt niet als `.env.production` de sleutel al zet:** dat bestand wint. Zet je een dienst aan met een nieuwe standaard, kijk dan met `sudo grep -c "^NAAM=" .env.production` of er een oude waarde staat (7 nov: Whisper draaide, maar de app zag `WHISPER_ENABLED=false`). Wijzigen alleen met sudo en eerst een kopie (`cp -p`), daarna `up -d --no-deps app`.
- **Caddy leest alleen `SITE_ADDRESS` en `BOUWER_VOORBEELD_HOST`** (`environment:` in `docker-compose.vps.yml`), niet heel `.env.production`: anders maakt elke nieuwe sleutel Caddy bij de volgende uitrol opnieuw aan en is de site even weg. Heeft de Caddyfile een nieuwe variabele nodig, zet die dan daar bij. Druk nooit `docker compose config` ongefilterd af: dat toont alle geheimen (ook van diensten waar hij van afhangt).
- PowerShell 5: `Out-File -Encoding utf8` zet een BOM; `git archive | ssh` beschadigt binaire data. Gebruik daarvoor Git Bash.
- **De server gebruikt de containerd-imageopslag: een image zonder naam bestaat niet meer.** Zodra een tag (`latest`) naar een nieuw image
  gaat, is het oude weg als het geen andere naam heeft; taggen op een image-id faalt dan met "No such image" (13 nov: de eerste
  terugzet-fix mislukte zo live). Houd een versie vast met een tijdelijke naam (`zekerflex-app:voor-uitrol` in `vps-update.sh`), haal
  alleen die naam weg met `docker rmi <naam>`, en laat een test met een nagemaakte `docker` deze regel nabootsen
  (`tests/vps-update-rollback.test.ts`). De terugzetversie (`rollback`) wordt pas na het bouwen en migreren vastgelegd, en alleen als de app echt veranderde.
- **Toon nooit een regel met een sleutel.** `crontab -l` in de cron-container, `docker inspect` en `env` tonen `x-internal-token` en andere
  geheimen; ook afkappen (`cut`, `head`) helpt niet, want de sleutel staat vooraan. Masker met `sed -E 's/(token: )[^"]+/\1***/'` of tel alleen (`grep -c`).
  Kapt ook tsc of eslint niet af met `head`: de fout in je eigen bestand staat dan juist buiten de eerste regels.
- **Script op de VPS via `ssh … 'bash -s' < script.sh`:** een `docker exec -i … psql -c` zonder heredoc leest de rest van het script als invoer en de controle stopt stil halverwege. `-i` alleen met een heredoc, anders weglaten.
- **`.env.production` is van root (600).** Scripts die er geheimen aan toevoegen (`deploy/scripts/env-aanvullen.sh`: SCRAPER_TOKEN, OUTLINE_*, OIDC_OUTLINE_SECRET, METABASE_ADMIN_PASSWORD) draaien met `sudo`; zonder sudo faalt het stil en start een dienst zonder token. Lees er nooit uit zonder sudo en druk hem nooit af (alleen namen: `grep -oE "^NAAM="`).
- **Nieuwe dienst in Docker:** eigen compose-service met `mem_limit`, eigen netwerk als hij code van buiten verwerkt (zoals `scraper` op `bronnen`), een Caddy-blok op `{$NAAM_HOST:<naam>.37-97-226-24.sslip.io}` (er is geen wildcard-DNS; de nette naam is een owner-todo), `up -d <dienst>` in `vps-update.sh`, en een eigen database via `deploy/scripts/databases-aanmaken.sh`. Een dienst die ingebed wordt (Metabase) hoort in de CSP `frame-src` van de héle omgeving (`lib/security/csp.ts`).
- **Eigen diensten loggen in met ZekerFlex** via OIDC (`lib/oidc`): een nieuwe client komt uit de omgeving (`clients()` in `lib/oidc/aanbieder.ts`), nooit uit een formulier; redirect_uri exact.
- Server-acties overleven een uitrol alleen door de vaste `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` in `.env.production` (compose geeft hem als build-arg; in Docker maakt Next anders elke build een nieuwe). Haal die niet weg en wissel hem niet zonder reden. Een tabblad van vóór een uitrol herlaadt zichzelf via `lib/ops/stale-deployment.ts`.

## Autonoom doel

Blijf waardevolle, begrensde verbeteringen bouwen (feature, fix, polish, SEO/content, admin-tool, performance, toegankelijkheid): bedenk zelf → bouw → verifieer → commit + push → kort documenteren. Zit je vast op een mensbeslissing? Noteer het en pak een andere taak.
